# Pre-flight Conflict Scan — rcedit v2 Implementation Plan

**VERDICT: 20 conflicts/defects found** — 1 cross-task interface MISMATCH, 3 tasks (T6, T8, T11) that are internally INCONSISTENT, 16 plan-vs-rubric/plan-vs-spec defects, and 3 additional documentation-only nits. Every *other* cross-task type/signature/enum/CMake contract matches cleanly (see Table 1). Two independent full-plan passes were run and cross-verified against each other and against the plan text directly (including hand-simulating the hexdump byte math); findings below are merged and de-duplicated.

Plan: `docs/superpowers/plans/2026-09-03-rcedit-v2.md`
Spec (binding): `docs/superpowers/specs/2026-09-03-rcedit-v2-design.md`
Scope: 11 tasks, Global Constraints, File map. All line numbers are plan lines unless prefixed `spec:`.

The headline: **almost every cross-task interface (produced-by-A / consumed-by-B) matches.** The errc enum, `Out`, `ResourceId`/`ResourceKey`, the `Codec` vtable, the `ResourceEngine` vtable, the `ops` signatures, `ParsedArgs`, the `CommandSpec::validate`/`run` function-pointer contract, and the `RCEDIT_TEST_GROUPS`/preset naming all line up across producer and consumer — with one exception (RC-language enablement, row below). The real problems are inside individual tasks: a compile-breaking undefined identifier, a missing CMake language declaration, a test that won't pass against its own implementation, a link-policy self-contradiction, a wrong build path assumed in two tasks, and plan-vs-spec drift the plan's own self-review undercounts.
